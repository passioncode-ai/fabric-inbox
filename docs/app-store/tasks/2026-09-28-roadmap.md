# Roadmap after the delivery decision — 2026-09-28

## Objective and entry point

Turn the mail workbench into a client that shows what matters, answers by itself where it is
allowed to, and serves project addresses. Three tracks, in the order the operator chose on
2026-09-28 ([decision](../architecture-options.md#decision--operator-2026-09-28)):

1. **P — project addresses and agents** (Cloudflare Email Routing, reusable agents with a reply
   policy and tools). UX: ST-008, FLW-08, SCN-021…025, SCR-09, SCR-10.
2. **L — local accounts and triage** (the personal and Workspace accounts synced on the Mac,
   important mail first, the rest collapsed by group and filter, account changes only by button).
3. **W — product page**, rewritten once P has something real to show.

Entry point: the first open packet in [Track P](#track-p--project-addresses-and-agents). One
executor, one branch per packet, `npm test`, `npm run typecheck`, `npm run build`,
`python3 docs/ux/lint.py` and `python3 docs/ux/doctor.py` green before a packet lands on `main`.

## Track P — project addresses and agents

### P1 · no mail lost

**Status: done 2026-09-28** on `main` — `tests/incoming-routing.test.ts` 8/8; full suite 157/157, typecheck and build exit 0. Two loss paths closed: an address outside `EMAIL_ADDRESSES` and a missing mailbox file. A processing failure was already rethrown in `workers/app.ts`; it now goes through the same `handleIncomingEmail`, and a planted removal of the rethrow was watched failing its test. NOT_RUN: a real bounce reaching a real sender (P6).

- **Defect:** `receiveEmail` returns without rejecting or storing when `mailboxes/{addr}.json` is
  missing (`workers/index.ts`, the `if (!(await env.BUCKET.head(...))) return;` line), so the
  message is lost and the sender learns nothing.
- **Change:** a per-domain unknown-address policy, `reject` (default) or `catch_all:<mailbox>`.
  Reject uses the Email Routing `message.setReject(reason)`; catch-all stores the message in that
  mailbox with the original recipient kept. Unknown recipients are recorded (address, time) for
  the "Create address" list of SCN-025. `DOMAINS` accepts several domains.
- **Tests first** (Miniflare pattern of `tests/`): unknown recipient with reject policy calls
  `setReject` and stores nothing; with catch-all stores once with the original recipient; a
  recipient on a domain the Worker does not serve is rejected; a duplicate delivery to catch-all
  is deduplicated; the unknown-recipient log never holds the body.
- **NOT_RUN:** a real bounce reaching a real sender (P6).

### P2 · agent registry

**Status: done 2026-09-28** on branch `agent/agents-triage-2026-09-28` — `workers/agents/registry.ts` (`AgentRegistryDO`, migration `fabric-v2`), assignment in `settings.agent`, legacy migration to `mailbox-<address>`; `tests/agents-registry.test.ts`, `tests/agents-runner.test.ts`. Deviation: runs are listed on SCR-10 (**Agents → Recent answers**), not in SCR-08.

- **Change:** `AgentDefinition` — id, name, version, instructions, knowledge sources, tool grants,
  reply policy — stored per version; a mailbox setting `agent: <id> | off`. The existing
  `agentSystemPrompt` of each mailbox migrates into one agent per mailbox, so behaviour does not
  change on upgrade. `EmailAgent` reads the assigned definition and version at the start of each
  run and records both.
- **Files:** new `workers/agents/registry.ts` (and its storage), `workers/agent/index.ts`
  (`getSystemPrompt` → the definition), `workers/index.ts` (mailbox settings), `app/types`,
  `app/routes/settings.tsx` → agent choice; SCR-10 UI.
- **Tests first:** one agent on two mailboxes; Off stops the agent while mail is still stored;
  editing an agent creates a new version and a run keeps the version it used; deleting an agent
  turns its addresses Off; the migration keeps every existing prompt.

### P3 · reply policy and autonomous send

**Status: done 2026-09-28, no live model** — `workers/agents/prefilter.ts`, `policy.ts`, `runner.ts`; the trigger is the durable incoming-event journal (the old `waitUntil` fetch never ran without the partyserver room header). `checkSendRateLimit` now reads the outbox budget instead of being called with its date bug. Model calls per mail: 0 for skipped mail, otherwise 1 injection scan + 1 agent call (up to 6 steps). NOT_RUN: a real Workers AI answer (P6).

- **Pre-filter before any model call:** `Auto-Submitted`, `Precedence: bulk|list|junk`,
  `List-Unsubscribe`, `List-Id`, no-reply sender patterns, and "the operator already replied in
  this thread" → recorded as skipped. This also removes most of the four model calls per mail today.
- **Policy decides send or draft:** allowed intents, an answer grounded in the agent's knowledge,
  a daily limit per address. Sending goes through the existing idempotent outbox
  (`MailboxDO.sendMail`), and `checkSendRateLimit` is finally called. Everything else is a draft
  with its reason, visible in the unified inbox (a Drafts view is added).
- **One run history:** agent runs join the automation history (SCR-08) with agent, version,
  decision and exactly what was sent.
- **Tests first:** each pre-filter header skips; a policy-allowed answer is sent once; an unknown
  send outcome is not retried; the daily limit turns sends into drafts; prompt-injection text in the
  mail cannot change the policy or grants; a model failure produces a draft, never a send.

### P4 · tools for agents

The MCP server's `send_*` approval item moves to the [audit backlog](../audit-2026-09-28.md#backlog).

Tests: an ungranted tool is refused; a host outside the allowlist is refused; a tool failure turns

- **L6** links to Fabric projects; needs a Fabric ADR, because Fabric ADR-0001 says Fabric neither
  reads nor writes personal mail.
